# Debug Dojo — Frontend

An AI-powered coding practice platform that teaches beginners to debug independently instead of handing them complete solutions.

The frontend uses a **Jujutsu Kaisen-inspired atmosphere**: dark, high-contrast surfaces, cursed-energy accents, sharp borders, restrained red/purple glows, and progression-themed UI. This is an original fan-inspired visual direction—not a reproduction of official anime artwork, logos, characters, or screenshots.

## Product principles

1. **Teach, don't solve:** explanations and progressive hints should guide learners toward their own fix.
2. **Evidence before AI:** the test runner determines what happened; AI explains the trusted result.
3. **Protect hidden tests:** never show hidden inputs, expected outputs, raw hidden exceptions, or private runner details.
4. **Practice makes mastery:** recurring mistakes should lead to targeted practice.
5. **Honest states:** distinguish loading, compilation, wrong output, runtime error, timeout, and infrastructure failure.

## Frontend stack

- React + TypeScript
- Vite
- Tailwind CSS
- shadcn/ui for accessible primitives and consistent components
- Sonner (`sonner`) for toast notifications
- `lucide-react` for icons
- React Router for page navigation
- Monaco Editor (`@monaco-editor/react`) for the coding area, if time permits

Use the shadcn/ui CLI to add only the components needed by the project. Typical components include Button, Card, Badge, Breadcrumb, Tabs, Resizable, ScrollArea, Separator, Tooltip, Dialog, DropdownMenu, Skeleton, Progress, Accordion, and Alert.

## Getting started

```bash
npm create vite@latest debug-dojo -- --template react-ts
cd debug-dojo
npm install
npm install react-router-dom lucide-react sonner
npm install -D tailwindcss @tailwindcss/vite
npx shadcn@latest init
```

Add shadcn/ui components as needed, for example:

```bash
npx shadcn@latest add button card badge breadcrumb tabs resizable scroll-area separator tooltip dialog dropdown-menu skeleton progress accordion alert
```

Install the Monaco wrapper only if using it:

```bash
npm install @monaco-editor/react
```

> Tailwind setup can differ by installed version. Follow the setup instructions generated by the current Vite/Tailwind/shadcn CLI rather than mixing configuration from different major versions.

Run the app:

```bash
npm run dev
```

## Suggested build order

1. App shell, theme tokens, routing, and toast provider.
2. Challenge listing using local mock data.
3. Challenge workspace with statement and editor.
4. Run/submit interactions and per-test results.
5. Progressive hints.
6. Learner dashboard and recurring mistake indicators.
7. Connect real API, test failure states, responsive polish.

Build a working end-to-end slice early. Do not spend most of the hackathon on decorative animations before the core submission flow works.

## Frontend scope vs backend responsibilities

The frontend displays results and collects learner interactions. It must not be the authority for:
- executing untrusted code;
- deciding hidden-test outcomes;
- storing secrets or hidden test cases;
- deciding that an AI hint is safe;
- calculating security boundaries.

These are backend/runner responsibilities. The UI must still handle malformed responses and API failures safely.

## Definition of done

- A learner can browse challenges, open one, edit code, run/submit, inspect visible results, request hints, and see progress.
- All four outcomes are presented distinctly: `passed`, `wrong output`, `runtime error`, `timeout`.
- Hidden tests are summarized without revealing their inputs, expected outputs, actual outputs, or raw exception messages.
- Responsive layout works at desktop and mobile widths.
- Buttons have loading/disabled states and meaningful accessible labels.
- Toasts confirm actions without replacing inline validation or critical error details.
